# 直播皮套式灵动：公开逻辑与当前模型配置核查

用户提出初始灵动目标尚未明确，参考直播皮套分析实现逻辑。本轮只读公开文档和本地配置，不安装/启动VTS，不反编译、不采集真人/生产数据、不训练。

公开依据：https://github.com/DenchiSoft/VTubeStudio/wiki/VTS-Model-Settings （本轮已读取）。VTS支持跟踪输入到Live2D参数的范围映射、逐通道平滑、自动呼吸/眨眼、物理、动画/表情叠加。平滑增加延迟。应用实现细节未公开处不猜滤波公式，不能将VTS Smoothing值当秒；PhysicsStrength=50的精确含义未由本轮确认，不写成50%。

本地`local-assets/fuxuan/unity-model/符玄.vtube.json`实际有19条ParameterSettings：FaceAngleXYZ→头AngleXYZ；同一FaceAngleXYZ→BodyAngleXYZ（输出±10）；头平滑15/15/30、身体20，显示同源耦合而非独立随机晃动；精确时间响应未测。眼开、眼笑、眼球、嘴形/开口、眉等映射存在，自动呼吸启用；自动眨眼开关均未启用（眼开来源为跟踪）。无默认idle动画、无hotkeys，不代表所有VTS模型都无动画。

physics3为50组，128输入/113输出，Fps60。已定位BodyAngleZ→Z2/Param251、BodyAngleX→X2、BodyAngleY→Y2。符合既有物理写入研究，不必重扫。VTS配置UsePhysics=true、Legacy=false、Strength50、Wind0，具体FPS枚举未解码，不猜成3Hz。全模型位置响应开启，X/Y/Z与平滑配置存在，与局部身体变形是不同层。

关键推论：直播皮套相当部分时序/相关性来自真人表演，VTS主要传递、映射和渲染，不应将流畅效果全部归为软件自动动作生成。可以复用本模型映射/相关驱动结构，不能仅凭配置恢复真人意图到运动的策略，也不能由视频唯一反解参数。自主角色需要替代的是跟踪输入背后的连续行为来源。

建议初始目标待用户确认：连续待机/听/说状态下的注意、头身耦合、眨眼呼吸/音频口型、物理余动；双臂语义动作作为后续增量，不删除已有节点路线。无需先完成泛化全身动作训练才展示基础灵动，也不宣称规则底座就是自主表达成功。下一实验若获确认：相同合成输入录制静态/独立随机/同源耦合分层对照，明确非训练、非真人跟踪，音频无输入不伪造唇同步；不自动开始新实现。
