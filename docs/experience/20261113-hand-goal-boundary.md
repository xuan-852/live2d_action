# 手目标优先：固定候选静态门槛（2026-11-13）

用户要求先考虑手与对象的关系、掌向和指形；若不能稳定展示就停止。本轮按测试前 PROTOCOL.md，先验收形状，未过静态门槛的候选不编成动态表达。

## 范围与结果

复用隔离 Unity 与原始素材，关闭物理，固定肩臂，13 个独立 SDK 静态样本；基础手7组、备用分支6组。不是连续动作，不声称保持/启动/停止或手势语义通过。未修改生产工程、SDK、拓扑、贴图、现有手臂或手指控制器。

- 基础手两组双指候选：没有清楚形成两根伸直分开的 V 轮廓，本轮失败。
- 两组收指候选：可见弯指，仍非紧凑闭合拳形，本轮失败。
- 基础手 Param100 正负固定候选：不足以证明所需掌面朝向；不把平面变形或转腕当翻掌。
- 备用手 Param92=1/93=1 在 Core 可见性有变化，但最终 PNG 未见手。尝试补调用 UpdateVisibility 后仍未显示，撤回本轮 LabMotion 改动，按任务前快照字节校验一致。保留诊断版本与前后输出；**备用手渲染链路未验证，不能据此判断模型无此能力**。

全部13组请求参数与 SDK 应用参数误差0，提交网格与 Core 几何配对差0；这只排除本轮请求数值未应用，不能证明可见形状或表达正确。原生作者参数±30；现有手指控制器±20是实验范围，不能叫模型上限。本轮固定候选未穷举，也不能证明其他组合不可行。

## 停止决定

没有新增手目标通过静态门槛，故不安排后续动态、MMD或换标签继续试。保留用户已认可的指向和已见弯指能力，不撤销既有用户判断；后两项整体表达仍不通过。当前可用表达集合应以已认可展示为准，不能承诺任意掌向/复杂手势。实际模型绝对上限尚未证明，尤其备用分支仍有证据缺口。
