- **原生目标控制修复（11-12）**：[五轴与有限逆解执行](experience/20261112-native-target-control.md)：用户指出抬不到头上并要求修复。旧三轴遗漏95/98、局部片段导数/停止近似卡住完整解、冻结终点未纠SDK上下文。新五轴复用已有标定，实际节点整步检查，原生响应预算单列；原最高点静态保持误差约2.6e-6，原源同帧.227→.000419，源腕RMS .250→.017，空间达标0→39/54。其余源9..23帧仍受限，不推广全模型不可达；补丁/自然度未新认证。94项实跑通过，MMD默认五轴，旧版用--legacy-native。
- **MMD接入首条回归（11-12）**：[实际反馈链路与失败分层](experience/20261112-mmd-timed-controller.md)：用户认可上一轮最后一列“不错，没有明显飘带感觉”，范围仅该版点任务。新控制器接入makoto-hair原54帧，不重定时/裁剪请求；两版各145帧SDK完成。89项测试通过；修复中性返回的局部解陷阱和float32加速度裕量，第二版安全门槛通过，但源跟踪失败。原生请求节点峰速2.10超过.72预算，缩短/分支亦受限；补丁触网格保护，最终保持仍略超位置门槛。未认证MMD动作保留，不扩数据/训练。
- **定时联合执行（11-12）**：[新版控制器与同请求消融](experience/20261112-timed-arm-controller.md)：85项实跑通过，保留3715个隔离SDK配对帧。区分hold收停/pass带速度经过/track保留路线；时间要求真正进入控制，沿用实际节点帧级保护。点目标补丁临时折腕24°→近0°，原生反向肘腕补偿显著减少；仅归一化不足。原生严格收稳 .867→.933秒、腕RMS变差，.6秒时限与变化身体跟踪仍有失败。用户后续认可该版点目标无明显飘带感，不推广全范围或MMD。
- **人体运动文献复核（11-12）**：[任务时域与协调](experience/20261112-arm-motor-literature.md)：检索8篇核心原始研究，纠正“掌滞后/关节不同步即错误”的泛化；腕时序依任务而异，旋前旋后也不等于平面折腕。代码核查发现 deadline 仅报告不参与控制，同目标 .3/1.2 秒只读探针30帧命令完全相同；reached 亦缺少任务要求的终端速度。优先验证任务时间内的联合执行，不直接套同步锁腕、最小jerk或人体力矩；尚未证明唯一力量感原因。
- **快档飘带/无力量感（11-12，用户反馈）**：[过渡姿态定位](experience/20261112-arm-support-diagnosis.md)：用户确认更快但指出像风吹飘带。实际 SDK 点目标中，补丁原本首末肘腕关系不变，过渡却临时弯肘约12°/折腕24°；近端已转80%时掌方向仅9%。原生也有反向弯肘/补腕。该片物理关闭，定位到未归一化任务代价与缺少中间姿态协调的执行问题；未证明唯一原因/修复，不继续单纯提速或宣称力感通过。

## 不再沿用的旧说法

1. “参考没有指根”：仅某些精简旁车没有；旧 MMD canonical 参考曾核实包含指骨。这不适用于本来就只有22点的 T2M。
2. “标准头部参数都是死通道”：旧调查曾用错地标；新模型应核对真正面部画件与可见响应。
3. “网格不翻转、相关系数高，所以动作通过”：本沙盒最近的整批观看失败就是反例。
4. “降帧率录制改成30fps就补好了中间帧”：重编码不能补回缺失状态；确定动作时间采样与实时性能分开记录。
5. “多播放器并发必定解释低帧率”：旧实验减为单实例后仍低帧，归因未成立。
6. “模型存在隐藏手形，所以一定能切掌背”：旧记录只证明有隐藏画件切换，画件画什么仍需可见画面确认。

## 如何继承而不把仓库重新变重

任务输入只需：本文件、任务说明、当前实现、相关 K 编号；需要细节时按 `sourceIds` 查具体文件和章节。外部路径是证据定位，不是构建/运行依赖；缺少旧文件时记录缺证据，不自动重建旧桌宠。

交接给下一位 agent 时携带五项：目标、相关案例编号、当前已验证事实、已否定解释、下一项可证伪问题。实现者可以采用不同算法，但应先解释适用的已知反例。

若要重做已有实验，先说明新变量/版本或需要独立复验的理由；避免把读过旧报告当作本轮已复验，也避免无理由重做相同失败。

每轮结束更新对应案例的适用版本、证据和状态；推翻旧结论时明确标记，不只在新报告末尾追加一句。文件太长时移动细节到按主题的案例，不无限追加启动必读材料。本文不增加旧代码、资源、模型权重或后台服务依赖。
