# 有状态手臂：限速与到位响应提速

关联 K01/K02/K07/K08/K09，承接 [受限控制器](20261112-stateful-arm-controller.md)。证据：`E:/FuXuanLab/runs/20261112-arm-speed-01/`。用户后续观察反馈“没有看出有什么问题”，主要情况是目标未到位、手臂太慢。该反馈绑定到上一轮展示的受限控制范围；用户未逐条指认视频/帧，不推广到旧失败版本或本轮更快候选。当前主问题据此转为到位速度，而非继续假定已有明显视觉故障。

后续纠正：用户确认新档响应更快，但指出“像被风吹起来的飘带，没有力量感”。因此本页数值提速结论不能当作动作质量通过；实际肘腕补偿与远端滞后定位见[后续诊断](20261112-arm-support-diagnosis.md)。

## 已确认的原因

- 旧原生首次切换目标的最大材料节点距离约 .33019；旧节点速度上限 .24/秒，仅按距离下界就需约 1.376 秒，无法满足 .6 秒截止时间。这是人为保守预算，不是模型静态位置不可达的证明。
- 旧补丁快速切换 90 帧有 45 帧顶到参数速度 45/秒；原生主要受材料节点速度约束，不能只统一放宽参数限速。
- 旧反馈每帧仅关闭 20% 剩余误差，到位末段存在长尾。因此同时调执行预算和反馈收敛时间，目标速度前馈的系数相应变化；不是放大动作或改播放速度。

## 最小实现

`stateful_arm.py` 新增显式 `speed_limits(profile)`：

| 档位 | 参数速度/加速度 | 节点速度/加速度 | 每帧残差反馈系数 |
|---|---|---|---|
| conservative | 45 / 180 | .24 / 1.8 | .2 |
| responsive | 90 / 720 | .48 / 7.2 | .36 |
| fast | 135 / 1620 | .72 / 16.2 | .488 |

速度预算按 k、加速度按 k²增长，名义停止距离不变；反馈系数为 `1-.8**k`，前馈系数为其补数。实际能否执行仍由整帧约束、非线性节点检查、停止前瞻、逐画件面积保护决定。没有关闭几何/连续性保护，没有改目标、路线、截止时间、帧率、模型绑定/拓扑/贴图/SDK，也没有训练或接 MMD。

本页版本的采集入口默认 `fast`。后续已默认使用 [定时控制器](20261112-timed-arm-controller.md)，复现本页所有档位须加 `--controller legacy`，保守档另加 `--profile conservative`。`ArmController` 裸构造保留兼容默认；直接调用时用 `ArmController(..., **speed_limits('fast'))` 明确选择预算。每帧增加 `limitingConstraints`，区分参数速度、参数加速度、节点包络及网格面积边界。

原 Unity 新控制入口存在固定 1.5/帧的第二层拦截，本轮改为显式环境预算除以 30，未设环境值时仍为 45/秒；有限值必须在 (0,180]。其他旧入口未改。首次 responsive 采集在第 59 条命令遇到 Windows `Sharing violation`，仅采完 58 个控制帧，不能当完成实验。原文件保留；针对原子重命名读回增加共享删除权限与仅分享/锁冲突的 2 秒有限重试，其他 IO/内容错误仍失败。responsive-r2/fast 及点目标批次均完整采完。

## 同请求 SDK 对照

在运行前固定：两侧各快速切换 3 秒、不可达后恢复 6 秒，540 个控制帧＋1 个初始化帧。同一 .6 秒切换截止时间、腕/肘 .005、掌向 4°、三角面积比实际 ≥.5、翻转/配对/恢复错误 0；各档按自身声明的速度/加速度门槛验收，不能冒充旧低速门槛。三组请求腕/肘最大差 0，掌向差约 8.5e-14°，时间/截止时间一致。

| 档位 | 原生腕 RMS | 原生错过截止帧 | 补丁腕 RMS | 补丁错过截止帧 |
|---|---:|---:|---:|---:|
| control-baseline | .15409 | 18 | .01689 | 18 |
| responsive-r2 | .12614 | 8 | .01393 | 0 |
| fast | .10232 | 1 | .01091 | 0 |

fast 腕 RMS 分别下降约 33.6%/35.4%，三个完整批次均无连续性 failed/翻转/配对/恢复错误；不可达后的最终恢复窗口通过。fast 仍有原生截止失败，不称全目标按时完成。最小面积比 fast 约 .54991，仍高于预定实际门槛 .5；规划目标 .55 是局部模型保护裕量，不能说每个实际值严格 ≥.55。

另有 `core-preflight.json`：只放宽预算、仍保留旧 .2 反馈系数的 **Core-only 预检**；不是最终反馈档配置，不与最终 SDK 数据混合。它保留了只调速上限时的有限改善，后续完整 SDK 试验使用表中的收敛系数。

## 明确抬到目标后保持

独立预定测试 `point-baseline`/`point-fast`：两侧分别接收同一固定节点姿态，保持 1.8 秒，再返回中性保持 1.8 秒；每次截止 .6 秒，不自动延长。原生目标由 [18,8,0]、补丁明确向外抬臂由 [-35,0,0] 构造，只把节点/方向输入控制器，不把生成参数当控制命令。判稳定到位需连续 3 帧腕/肘/掌向同时达门槛；保持窗口固定为 45..53、99..107 帧。

| 侧 | 旧档稳定到位/回收时间 | fast 稳定到位/回收时间 |
|---|---|---|
| 原生 | 两个 1.8 秒阶段内均无连续 3 帧稳定到位 | .733 / .733 秒 |
| 补丁 | 1.700 / 1.667 秒 | .533 / .467 秒 |

fast 两侧保持窗口均通过，旧档均未通过；fast 原生仍错过 .6 秒截止时间（共 8 帧），补丁截止时间均满足。两批均无连续性 failed、翻转、配对或恢复错误。新档尚未获得用户视觉认可；数值说明它更快到位，不证明任意速度自然或任意位置可达。
