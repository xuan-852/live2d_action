## 已核查事实

- 原8条整体动作的 depth 全程 `(forearmFront=1, handFront=1)`；不是丢失了一条原有的前后变化曲线，数据本身就固定在前。
- 旧整体基线已消费补丁投影长度。上臂最短0.75–0.99，前臂多数最短0.75。不能说投影完全未执行；问题是执行效果与适配是否合理未被评估。
- 当前 SDK 实际 `SortingMode=BackToFrontZ`。上轮只做固定 Z 偏移，没有逐帧深度路由，也没有与具体衣物层级的显式关系约束。

## 实验

两例：novel-01，novel-12（沿用留出）。同一源动作、同一角度、相机、身体、物理与时间；只改补丁侧。每例四个版本：

1. legacy：上一轮固定Z前移，原投影。
2. front：极端绘制顺序前置，原投影。
3. behind：极端绘制顺序后置，原投影。
4. unshortened：前置，投影上/前臂长度固定1。

极端顺序±1000只用于证明遮挡能改变图像，不是画件分层方案。不作前后切换运动，也不伪装为源深度恢复。对照只覆盖补丁臂；原生Param95/98的投影与层序控制仍需独立对照。

8段合计1392帧PNG/JSON；每例四列视频 `<id>-layers.mp4`；静图 `layer-comparison.png`。恢复误差均为0。投影关闭后最小面积比由0.595/0.602升至0.765/0.880，这只是数值现象，不证明关闭缩短更正确。

纠正：此前“前/后会分别让补丁前臂与手显示在胸口服装上或被衣服覆盖”的观察只适用于处理到的局部，**不能推导整条手臂遮挡已正确**。用户随后明确反馈“衣服还是把手臂挡住了”，本轮遮挡修复不成立。取消缩短改变手位和袖口轮廓；不能靠藏起手臂改善表达，也不能把±1000前置当最终修复。
