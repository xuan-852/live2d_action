# 从手形到三个整体表达候选

## 后续用户审看与设计纠正

用户确认第一项“指向”在本视频里表达清楚；后两项看不出意图。进一步指出问题不只是缺乏情境，而是手根本不应那样展示：手是主要任务端，朝向和手指动作本身改变含义。故只把coordinated-02第一项保留为本段整体指向的认可锚点；后两项不通过，不能靠保持误差低、加标签/情境升级为好表达。

代码核对：OFFER/BEAT/NEAR先选了近端/腕部参数种子，再配open-accent/soft-curl手形，只有指向任务有明确的方向关系；后两项主要检查位置与阶段。应先定义手要完成的任务、掌面/主指方向、指形与接触关系，再组织肩肘腕路线。平面掌向角不等于掌面法向，不能用平面折腕替代翻掌，也不能把手接近头部等同于接触/整理。

本次复核原始研究：[Li等，2017](https://users.wpi.edu/~zli11/papers/J2017_Rosen_Reach2Grasp.pdf)的实验摘要说明抓握位置/朝向会改变手臂姿态，不只是把手运到位置；[Kendon，2004原始观察总结](https://www.cambridge.org/core/books/abs/gesture/two-gesture-families-of-the-open-hand/C9BDAFEA757966C69DD41ACEA26FDBBA)区分掌心向上/下的开放手势家族；[2021会话原始研究](https://www.frontiersin.org/journals/communication/articles/10.3389/fcomm.2021.663067/full)进一步显示掌心向上动作的交际功能依赖实际话语和互动。没有据此规定所有文化、语境下固定含义，也没有把人体三维机械模型直接套进Live2D。

下一步先建立手中心的任务描述与能力边界，先审手的展示是否符合意图，再扩成整臂表达。当前二维/作者参数实现没有任意掌面朝向保证，支持不了的要求必须明报；不继续通过缩小/剪切手形伪造。此轮仅复核与记录，未改控制器、未新录动作；不能沿用前述数值通过认证后两项。

日期2026-11-13。用户认可上一轮原生手指灵活度可作为复杂表达基础，批准推进“指向、解释强调、接近头部”的整体表达实验。随后明确：旧手K没有具体手部、尤其手指动作，不宜用作目标，可以修改或新编。本轮据此新编三项受控场景，不把旧手K或动作名当手势真值。

认可锚点是 `20261113-gesture-exploration-01/revision-02` 的原生手指可动/组合表现，不扩展为新任务语义或自然度认可。新证据根 `E:\FuXuanLab\runs\20261113-intent-expression-01`；开始git状态、diff及修改前文件保存在baseline。无自动提交推送，未改生产桌宠/服务。

## 方案与职责

复用原生五轴节点控制、五指SDK实际反馈执行、既有头身输入；新增显式可选的双眼参数执行和最终SDK材料点读回。没有修改模型拓扑、贴图、第三方SDK、补丁腕点、旧手臂预算或手指执行器。补丁保持中性，整手投影为identity。

三项是**人工编写的诊断请求**，不是学习出的上层策略、通用语言到动作模型或动作库。原生参数种子只在规划端构造有限可达的材料节点路线；下层收到腕/肘/掌向和逐帧速度、手形点目标、头身/眼球要求，不收到源参数作为手臂执行命令。阶段边界用新编的固定30Hz时钟，不对实际录像补帧或事后重定时。

- 指向：先转头/移眼，随后伸臂形成单指，保持后收回。目标A在采集前由参考端点构造并冻结，不能根据实际误差移动。材料轴indexBase→indexTip作2D指向代理。
- 解释强调：准备→展开呈示→轻收拢强调→再次展开→收回。头眼主要朝观众，手指变化与手臂阶段一起发生。没有生成台词或证明解释语义已被识别。
- 靠头：保持轻收拢，接近头侧区域后停住，再退出；不宣称已经接触。以掌材料点相对headSide的距离/偏移作放置检查，未提供手指/发饰碰撞系统。

眼球入口使用ParamEyeBallX/Y，范围±.8、速度3、加速度15（作者单位），保留实际值/速度/未完成点目标并报告受限。以少量已知眼球干预确认正X/正Y分别移动可见眼部到画面右/上，没有全参数扫描。眼参数和瞳部材料位移只验证方向提示，不是校准过的三维视线或注视点。

额外SDK材料点包含食指相关网格的近端/远端候选、头侧、双眼部件中心。它们来自最终提交网格，独立于控制器预测。远端候选是中性网格离腕最远的固定材料顶点，可能包含透明边缘，不能冒称像素轮廓尖端或人体关节。headSide是头网格的材料采样，也不等于三维太阳穴。原四点手臂读回保持不变。

## 采集前门槛与版本变化

在DESIGN.md和acceptance-protocol.json固定：express/rest最后15帧，腕/肘误差≤.005、掌向≤4°且原生终端状态收稳；手指误差≤.15/速度≤.5，眼参数误差≤.02/速度≤.05。指向代理角≤6°，靠头掌/头侧距离.02–.09模型单位。原手臂/指速度、加速度和SDK逐帧守卫不放宽。物理关闭，只验证当前受控上下文。

首版coordinated-01与同路线neutral-fingers-01各448帧，数值执行通过。目视复查发现近头手指跨进发饰区域，头眼方向提示也偏弱；这不是新的数值跟踪失败。第二版将靠头腕方向转向外侧、指向头/眼提示加大，并把准备段.4秒改成.5秒供眼球收停。改变的是**新编目标和场景时长**，不能称为在完全相同目标上提高控制精度。两版完整保留。
