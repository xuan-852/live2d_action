## 已否定的解释与实际原因

1. 不能从旧控制器静态求解失败推断模型不能高举。旧原生适配器只用Param94/97/99，没有接入已研究的Param95/98缩短响应。相同最高点请求（源frame28，腕[.1222241091,.5060981649]），旧三轴静态残差约.196；直接复用已有方向/长度标定表初始化五轴再Core局部求解，离线腕残差小于1e-6。没有全参数扫描或重新猜节点。
2. 只加轴仍不足：旧速度预算下五轴源腕RMS反而.25698；原生最高点仍未跟上。中间版将预算提到1200/60000、节点3/150，仍在Core变形片段边界绕行。记录显示完整逆解已找到目标，但当前点雅可比把跨片段运动预测错，局部帧级目标无法执行那个解。
3. 原有停止距离用局部雅可比把节点加速度再换成参数制动预算，并乘3的保守因子。对Live2D软件变形轴，这不是机械惯性；已知完整逆解且能验证实际节点时，这层近似会额外卡阻。不能因为“安全层”命名就把其保守性当作模型能力。
4. 固定终点参数不等于持续保持实际目标：SDK身体/物理上下文后续变化时，首次拟合参数会留下约.00524的高举静态残差。不能只盯计划参考误差。源速度原用中心差分，而SDK速度是已执行区间差分，也会给精确位置跟踪制造速度语义冲突。

## 实现与界限

- 新 `NativeTargetController`，五轴顺序 **94、95、97、98、99**。从现有 `calibration.json` 的上臂方向/长度、前臂弯曲/长度表初始化，消费当前实际上下文，Core联合细化腕/肘/掌方向。延续上一参考解初始化；中性仅为受限回退，求解候选不直接重置执行器。不训练逆解网络、不扫描244参数。
- 新原生求解盒范围取模型真实参数边界内.01单位，替代旧三轴较大的.5/.2裕量；触边仍报告，近边界全范围自然度不作保证。旧三轴与补丁范围不变。
- 底层状态/安全投影推广到执行器维数；3轴补丁/旧控制不变。五轴QP先用小活动约束集，只在原始约束可行且KKT乘子非负时返回，否则退回精确约束面枚举。不把求解迭代累加成多次帧步。
- track每个原样本得到一个完整有限逆解候选，**只有实际非线性节点整步、参数盒约束、整帧速度/加速度及停止检查全部通过**才直接执行。局部雅可比近似不再有权否决一个已证实满足这些条件的完整候选；不满足时仍走受限局部步。记录 `finiteTargetAccepted`，不隐瞒限制。
- 原生停止预算用声明的执行器加速度，随后依然逐步调用Core验证节点停止轨迹；参数边界、节点速度/加速度及读回检查保留。补丁继续使用原停止近似与网格保护。没有改变SDK、模型、贴图、物理配置、获认可腕点、头身映射。
- hold在原deadline后持续按当前实际上下文重拟合并反馈纠偏，**不重启deadline**，保留超时报告。源track绕过到位连接器，不逐点停车。
- MMD输入速度改成与SDK反馈一致的原相邻样本区间差分；获取段已经在首点保持，源第一个速度为0。原腕/肘/掌方向、源54个时间点、头身输入完全不变，未通过缩小目标、改速或删帧改善结果。
- MMD入口默认用五轴原生后端；复现历史三轴加 `--legacy-native`。直接试验工具 `native_target_trial.py` 用五轴；一般旧fixture入口仍默认旧三轴，可从Python `run(..., native_five=True)` 显式选择。

## 预算与验收（采集前写入protocol）

静态高举使用原fast预算：参数135/1620，节点.72/16.2。原最高点保持3秒，deadline2秒，再中性返回保持3秒，deadline5秒。两段最后15帧腕/肘≤.005、掌向≤4°，实际所有节点速度≤.02、掌角速度≤8°/秒。头身/原SDK物理开启；补丁只是同场中性参照，原生任务成功不代表补丁同场保持通过。

原生MMD路线预算单列：**参数速度2700、加速度162000；实际节点速度3、加速度180**。这是30Hz软件变形执行预算，不是人体力矩/力量感标量。参数允许一帧最多90单位，近似覆盖现有轴范围；真正画面位移仍受实际节点约束。补丁仍135/1620与.72/16.2，未统一放宽。隔离SDK入口仅在显式五轴协议下允许该预算，三轴仍保留180最大设置。

这次确实改变了原生响应预算，不能冒称在旧限速下解决了原曲线。轨迹没有重定时，安全检查使用新声明门槛，不能用旧低门槛宣称通过。通用全局/全参数可达性不在本轮承诺内。
