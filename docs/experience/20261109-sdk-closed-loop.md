## 实现与冻结协议

新增`LabMotion.RunControl`与`tools/control/closed_loop.py`，每帧Python原子写命令，Unity执行物理/Core/渲染并保存PNG/JSON，再写ready；Python读取实际状态后才决定下一帧。不预先算好曲线。固定物理步长1/30，等待命令不推进动作时钟；不是实时性能认证。35项Python测试通过，Unity实际编译及4次完整运行成功。

seed8031，两组新初始目标，每组181帧、约6秒，目标A/B/返回在0/60/120帧切换，身体X/Y持续变化。共724对PNG/JSON。目标由Core实际原生臂响应生成，但固定在中性身体坐标，因此不保证每个变化上下文中四坐标精确可达；这是任务限制，不能把残差全部归因控制器。初始q=0，两执行器仍为Param94/97，范围与静态首轮相同，每步增量≤1.5。

历史模型直接冻结上一轮`True-history`权重，本轮无再训练或按测试调参。它用局部预测Jacobian与正则反馈选择下一步，非直接策略网络或RL。普通数值反馈用当前完整applied参数在独立Core做局部扰动查询，因此**同帧数、同限幅，但不同观测/计算预算**。不能宣称纯算法同资源公平胜负。

成功门槛：每阶段末10帧四坐标RMS均值<.005；无连续性、安全、像素可见性通过门槛。最后多一帧仅作状态/录像保留，不纳入阶段统计。
