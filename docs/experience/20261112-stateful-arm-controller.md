## 简短设计与边界

- 接口：`tools/control/stateful_arm.py` 的 `Target`、`ArmController.command/observe`。坐标为模型局部二维，x 向画面右、y 向上；native=画面右/解剖左，patch=画面左/解剖右。腕位置、可选肘位置/弯曲分支、掌轴方向、可选肩根要求和截止时间都显式传入。肩根独立平移不支持，会报告；身体上下文由宿主与 SDK 执行，后端消费实际应用参数/源网格，未假定可访问三维人体骨骼。
- 保留上一帧实际材料节点、应用执行器、节点/参数速度、近期请求、解支与未完成目标。`requested/ideal/actual` 分开；实际残差、deadline、连续受限帧、分支变化和失败原因逐帧记录。掌向约束是相对腕的二维方向，不是另一个独立掌位置或掌面法向。
- 原生：复用已认可范围内的材料绑定和 Core，最小版本只控制 Param94/97/99，Param95/98/100 不作为主动自由度。每帧用最后 SDK 的**全部应用参数**作为局部响应上下文，再用实际节点修正局部模型；不学习参数逆解，也不预测 SDK 物理内部演化。角度限制来自本模型并留肩/肘边缘余量。
- 补丁：复用认可的 axis-wrist 四点及现有 ShoulderConnection/MLS、袖口变形与最终网格读回。三个角度连续求解，无逐帧角度逆解换圈；投影锁定 identity，未独立裁剪长度，未改变绑定、拓扑、贴图、SDK 或整体动作系统。补丁材料肩点、执行 socket、理想链和视觉关节仍不等同。
- 一次整帧约束步：参数速度 45 单位/秒、加速度 180 单位/秒²；材料节点速度 .24 模型单位/秒、加速度 1.8 模型单位/秒²。参数浮点读回比较容差 .001。QP 活跃面枚举避免近乎平行约束的迭代假不可行；非线性重线性化始终使用同一帧原点和预算，最后只执行一次。
- 检查冻结上下文中的可刹停路线，避免进入下一帧无法满足约束的状态。局部有限步候选只在当前三轴帧预算内检查，不是重扫 244 参数。目标差分前馈用于保持路线节奏，位置/方向反馈关闭残差；不缩放输入路线，不自动延长上层截止时间。
- SDK 返回 16 个现有补丁画件各自的最小三角面积比及局部梯度；逐画件约束规划面积比 ≥.55，实际验收 ≥.5。停止前瞻使用相同边界，避免全局最小画件切换时丢掉尚未激活的约束。局部模型不能保证任意外部扰动的未来可行性；不能求得安全步时明确 failed，实际越界也会 failed，不静默当执行成功。
- 局部固定长度包络外、肩根要求、分支冲突、截止时间错过、局部停滞、几何/连续性异常分别报告。局部停滞不等于全模型绝对不可达，也不保证固定腕能任意换肘。

SDK 入口是新增 `LabMotion.RunStatefulControl`；旧转换器与旧入口原样保留。本轮给 WholeArmSession 增加读回与无提交的几何局部测量；`RecoveredShoulderConnection.cs` 的既有用户差异未改动。`nativeDistalFront` 显式开启，仅为已有七个原生远端画件的审看路由，不认证通用深度排序。

## 验证与失败版本

初始完整 unittest 实跑 64 项通过；新增控制/约束/扰动/截止时间/逐画件切换回归后，完整 73 项通过。Unity 批次均实际运行并保存 complete.txt、逐帧无损 PNG/JSON、实现快照与 protocol.json。每批在测试前写范围、时间与门槛，以下版本改变了测试时长/连接方式，不能把不同版本当作完全同输入的因果 A/B。

| 批次 | 帧对数（含初始化） | 保留结论 |
|---|---:|---|
| direct-v1 | 1201 | 小型迭代 QP 假不可行，独立轴应急减速造成连续性失败；完整失败录像保留 |
| direct-v2 | 1201 | 原始同时间目标下无连续性失败，但路线滞后、补丁不可达段面积比约 .353；不能通过 |
| direct-v3 | 1321 | 加前馈、连续进入路线、升降各两秒；原生四秒路线仍有腕/掌向及截止时间残差；补丁不可达段无几何保护 |
| direct-v4 | 1441 | 六秒同空间路线通过；只约束全局最小面积梯度导致两次补丁急停；原生四秒恢复窗口肘尚未到位 |
| direct-v5 | 1561 | 逐画件几何约束、同边界停止检查、六秒恢复试验；详见下表，未隐藏目标切换失败 |
| body-physics-v5 | 181 | 原始 SDK 物理开启，输入 BodyAngleX=2 sin(t)、Y=1.5 sin(.7t)，双臂组合；安全门槛通过，精确跟踪未全过 |
| patch-visible-lift-v5 | 211 | 针对原样例肩肘抵消的问题，额外检查清楚的向外抬起；不是替换旧样例 |

直接任务的预定到位门槛：腕/肘误差 ≤.005、掌向误差 ≤4°。抬起保持检查局部第 90..119 帧，放下保持 195..209；转腕与六秒连续路线检查所有帧。切换目标只有固定 .6 秒 allowance，不随执行滚动延后。不可达目标 y+ .8 在 .5..2 秒施加，2 秒返回可达目标，最终检查最后 15 帧。恢复总时长从四秒改为六秒是**另一个预先声明的测试**，没有改写旧请求或宣称原四秒通过。

| 任务 | 原生 | 补丁 |
|---|---|---|
| 到位/保持/放下窗口 | 通过 | 通过，但原补丁样例视觉幅度资格有限，见下文 |
| 单独正负转腕（±20°） | 全帧位置/方向门槛通过 | 全帧位置/方向门槛通过 |
| 连续腕路线＋肘/掌向，六秒 | 全帧门槛通过 | 全帧门槛通过 |
| 移动中切换目标 | 连续性/报告通过，截止时间未全满足 | 连续性/报告通过，截止时间未全满足 |
| 不可达目标后恢复 | 报告包络/残差，最终完整肘腕/掌向窗口通过 | 同左，几何边界限制实际展开，最终恢复窗口通过 |

direct-v5 全段实际节点最大步长：原生 .00799215、补丁 .00799690；最大节点加速度分别 1.77303、1.36362。帧级参数最大变化均 1.5；无记录到的异常换支、翻转或连续性 failed。最小三角面积比 .55000055；pairing/restore 最大值均 0。限幅持续时间、每帧残差和约束原因见 `assessment.json` 与 `track.jsonl`，不能把这些数字单独当作自然度或支撑感认可。

**测试设计纠正**：原补丁到位样例是 shoulder=-35/elbow=65/wrist=-15，肩肘相互抵消，腕仅向上约 .021、向内约 .034。旧数值门槛通过只证明该节点要求的执行，不能称可读的抬臂已被证明。额外 `patch-visible-lift-v5` 保留同一肩角 -35，肘/腕为 0；请求腕向外 .16144、向上 .10799。完整 2 秒抬起、2 秒保持、2 秒放下、1 秒保持，两个保持窗口均通过；实际最小面积比 .65148、最大节点步长 .00425018、最大节点加速度 1.37617，无 failed/翻转/配对/恢复错误。固定裁切静帧可见手臂向外抬起，但动态路线、袖口/连接和支撑感仍未获用户认可。

body-physics-v5 无安全越界，但原生 1/180 帧、补丁 13/180 帧未满足全部精确跟踪门槛；最大腕误差分别约 .00556/.00791。补丁还报告独立肩根要求/分支冲突。不能宣称物理上下文已全面解决，更不能把原生 Core 静态响应认证为任意物理状态的动态模型。

- 已否定：单次迭代限步等于整帧限速；单帧局部可行等于下一帧可刹停；全局最小网格的梯度足以保护所有网格；只看掌/腕误差可证明整个恢复；测试名叫“抬起”就能证明画面可读；数值全过等于有支撑感。
