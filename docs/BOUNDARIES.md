# 边界与准入

## 独立性

本项目必须能在没有桌宠主仓库、桥接服务和生产记忆的情况下运行与验证。

`runtime` 不依赖预览 UI、录制脚本或桌宠业务。`preview` 只装配运行时与显式测试控制。`tools` 消费明确的数据格式，不读取主项目内部状态作为隐式依赖。

未来生产接入只消费经过验证的运行时包与版本化动作产物。具体接口和包管理方式尚未决定；本次不添加 submodule、UPM 依赖或生产适配器。

## 网格与动作分别迭代

初始背景：旧项目使用原生手臂通道与用户补充的另一侧网格。具体画面方向、模型版本、执行状态和可达范围必须在本项目重新核对，不把旧报告结论直接当作认证。

补丁网格本身不完善，需允许迭代：

- 肩根连接与遮盖、上臂/前臂/袖口/手的绑定与拓扑；
- 变形下的纹理拉伸、三角形翻转、面积退化与关节连续性；
- 前后遮挡、层序、衣袖与装饰的分离；
- 手型、模型可达范围及需要补画或重新绑定的部分。

不预先断言某个画面缺陷是模型硬上限，也不把测试保护阈值直接当成自然动作范围。每次只改变明确变量，并以固定动作与人工画面对比验证。

## 旧资产准入

引入前记录：来源与精确版本、用途、许可证、直接依赖、可复现入口、已知缺陷。候选代码必须去除主项目隐式依赖并增加对应验证，不能直接继承可信状态。

保留已认可动作作为不可覆盖的回归样例；旧实验帧、构建和完整历史保存在原处，本次不移动或删除。
