# 启动计划

## 阶段 0：独立仓库（本次）

- 建立远端、本地 Git 仓库、最小目录与协作边界。
- 建立可运行的骨架检查。
- 不复制旧代码、模型、SDK，不清理主项目。

## 阶段 1：最小可复现预览（待实施）

1. 确认 Unity/团结版本及 Cubism SDK 许可和版本，建立独立工程。
2. 经资源许可检查后导入固定版本模型，建立来源清单。
3. 只保留明确的参数写入者，显式记录物理状态，先验证中性渲染稳定性。
4. 实现固定动作时间步的无损采集；图像与状态可靠配对；分别记录动作时间、墙钟时间和耗时。
5. 验证孤立运行、失败清理、可复现性与均匀采样。没有这些证据，不开始规模化生成。

## 阶段 2：补丁网格质量（待实施）

隔离引入需要的补丁实现，先复现基线，再迭代肩根、绑定、拓扑与层序。用相同动作和视角比较旧版/新版；数值质量与人工视觉判断分别保存。无需为了沿用旧实现而冻结网格。

## 阶段 3：动作研究（待实施）

建立中性、单侧动作与双侧协调的小型测量集。以手、肩、头、躯干的可见关系作为重定向目标，而非仅按名称映射或将动作压缩成一个活动量标量。具体生成/优化算法在测量闭环成立后决定。

## 阶段 4：发布与产品接入（未启动）

验证独立运行时和动作数据的版本契约，再讨论 Unity Package/submodule 与旧产品适配。主项目代码化简单独安排，不混入本仓库启动任务。
