## 改了什么与能力边界

- 保留 `stateful_arm.ArmController` 作逐帧旧基线，复用原生 Core 响应、补丁几何、实际 SDK 反馈和整帧安全投影。新增 `timed_arm.TimedArmController`；验证入口默认新版，旧实验必须指定 `--controller legacy`。没有改模型、SDK、C#、拓扑、贴图、已认可腕点或头身驱动。
- `Target` 新增 `mode='hold'`、可选二维腕速度 `velocity` 和掌向角速度 `angular_velocity`。坐标仍为现有模型局部二维坐标，臂身份显式 native/patch；节点顺序肩/肘/腕/掌材料点，掌方向为腕→掌的角度。材料链角度不是人体真实关节力矩。
- **hold**：在原定 deadline 内连接姿态并收停，终点要求实际所有节点速度 ≤.02 模型单位/秒、掌角速度 ≤8°/秒，同时腕/肘误差 ≤.005、掌向误差 ≤4°。位置碰到目标而仍移动不算到位。
- **pass**：必须给腕终端速度，可给掌角速度；经过点后继续运动，不在每个路点停车。无法满足的终端速度返回残差/限制。宿主仍负责及时提供后续目标。
- **track**：直接跟随上层给定的原节点路线/时间，绕过点目标连接器；不插入任意手势、不强制路线点停住。
- 对仅给终点的 hold/pass，局部拟合可执行参数终点；从实际参数、速度、近期加速度构造带边界条件的五次连接。相同任务包不会因时钟舍入反复重启。中途换目标继承实际运动状态。位置与参考速度共同进入下一步目标，保留收停意图；不是事后平滑。
- 肘/腕位置和掌方向误差按验收容差归一化；终点连接对不必要的执行轴绕动给软代价，**不普遍硬锁腕或肘，不保证任意固定腕换肘**。没有显式路线时，这是受限下层插值策略，不是人体最优控制结论或上层动作学习。
- 保留参数/实际节点的帧级速度、加速度、停止前瞻、非线性几何检查。补丁仍周期 wrap、实际网格读回；原生仍使用实际应用上下文更新局部响应。请求、参考可执行节点、实际节点和执行残差分开保存。不可达/冲突/超时仍报告，不延长 deadline 或缩小全部动作冒充成功。

## 预定验证与版本保留

先写 `comparison-protocol.json`，同目标/同 .6 秒截止/同30Hz时间/同 fast 预算：参数速度135、加速度1620；节点速度 .72、加速度16.2。实际网格面积比 ≥.5；翻转、配对、恢复错误为0。三帧连续满足位置/方向及终端速度才算稳定。相对旧版严格收稳时间最多退化 .15 秒；原生反向肘 ≤5°、腕绕动 ≤5°，补丁肘腕绕动 ≤2°。视觉结论另判。

保留 legacy / normalized / timed 三组消融，各217个SDK配对帧；suite-01 1333帧、body-01 181帧；最后源码重新录制 timed-final 217帧、suite-final 1333帧。合计 **3715个SDK配对帧**（含各批初始化），不是3715个不同任务。所有完成批有逐帧 PNG/JSON、实现快照和完成标记。中间版与失败预检全部保留，不仅留最好结果。

离线预检 preflight-01/02/03 仅为 Core/理想补丁，不冒充 SDK：曾出现只追位置参考、限速后丢失制动而上臂越过终点（约 -39.4° 对 -35°）；改为同时跟随参考位置/速度。另修复相同任务包时钟误差重启连接、非活动臂滚动 deadline 的宿主问题。最终完整录制包含这些修复。

| 原生材料腕最大绕动 | 36.46° | 约 .0022° |

只做归一化的 normalized 仍有原生反向肘约38.7°、腕约24.6°与补丁肘约13°，不足以解决过渡补偿。新连接减少了这个任务中不需要的绕动，但**不是所有误差都更优**：启动更渐进，腕位置RMS增大；原生严格到位慢2帧。实际峰值节点速度原生 .716→.677、补丁 .719→.613，虽然预算没改，不能说每个时刻速度不变。两侧严格时间退化均在预定 .15 秒内，补偿门槛通过；原始 .6 秒要求没有全面满足。共同严格标准下超时帧原生16→20、补丁3→2。旧文档 .733/.533等数字仅用位置/方向，不能直接与本轮严格收停时间比较。

最终组合 suite-final：两侧给定连续路线、正负转腕全帧误差门槛通过；移动换目标的报告/安全门槛通过，**原生并非所有新目标按期到位**。不可达返回原因并在回到可达范围后通过最后15帧恢复窗。两侧 pass 均在非零指定速度下经过节点、继续运动，再切换保持通过。所有最终安全检查通过，最小实际面积比 .549993（高于预定 .5，不宣称严格≥规划裕量 .55），无 failed、翻转、配对或恢复错误。

body-01 使用原 SDK 物理及小幅身体变化：未出现安全失败；原生仍有个别路线帧误差超限，补丁虽过位置门槛仍报告执行器/分支/肩平移能力限制。此批为 track 模式，不认证变化物理下任意 hold 终点，也不认证一般身体组合能力。

## 当前结论与未解决项

已证实：deadline 进入控制；到位/经过/跟路线有不同终端语义；本点目标不必要的反向肘腕补偿显著减少，实际帧级保护未失效。

不再采用的解释：只需继续提速；只把方向代价归一化就够；所有掌滞后都错；统一锁腕/关节同步可代表人体规律；位置到达等于收稳。新结果不能证明此前“无力量感”的唯一成因，更不能凭角度数字替用户判断画面。

仍未解决：原生更快的限时到位、位置误差与过渡姿态的权衡、变化身体/物理下跟踪与终点能力、画面连接/启动停止/支撑感的人工审看。未接回 MMD、训练网络、扫描全部参数或更改模型结构。开始时 status/diff 和8个直接文件快照在 baseline；新增涉及的审看器差异另留基线对照。未提交或推送。
